# Flutter & Backend Localization Architecture Analysis

## Overview

This document provides a complete technical analysis of the **Localization (i18n / l10n)** system in the JustUS application, covering both the Flutter frontend and the Node.js backend notification engine.

The platform supports two languages:
- **Italian (`it`)**: Default primary locale and fallback language.
- **English (`en`)**: Secondary supported language.

---

## System Components

### 1. Flutter Localization Core

- **`LanguageHelper`** ([language_helper.dart](file:///f:/JustUS/Flutter/lib/core/localization/language_helper.dart)):
  - Defines constants: `storageKey = 'app_language_code'`, `fallbackLocale = Locale('it')`.
  - Maintains `supportedLanguages` catalog (`AppLanguage` objects containing `code`, `englishName`, `nativeName`, `flagEmoji`, `aiTranslationHint`).
  - Resolves locales with fallback fallback logic (`resolveLocale`, `resolveLanguageCode`).
  - Implements `localeResolutionCallback` for Flutter `MaterialApp`.
  - Manages static `AppLocalizations? _appLoc` for non-contextual or background isolate translation access (`LanguageHelper.appLoc`, `LanguageHelper.initFromSystemLocale()`).
- **`LanguageProvider`** ([language_provider.dart](file:///f:/JustUS/Flutter/lib/core/localization/language_provider.dart)):
  - `ChangeNotifier` state manager controlling active app `Locale`.
  - Persists and loads locale preference via `SharedPreferences`.
  - Updates `LanguageHelper.setAppLocale()` on change and notifies UI listeners.
- **`AppLocalizationBuildContext` Extension** ([localization_extensions.dart](file:///f:/JustUS/Flutter/lib/core/localization/localization_extensions.dart)):
  - Exposes `context.loc` shorthand extension returning `AppLocalizations.of(this)`.
- **Generated `AppLocalizations`** ([app_localizations.dart](file:///f:/JustUS/Flutter/lib/core/localization/generated/app_localizations.dart)):
  - Flutter `gen_l10n` code generated from `intl_it.arb` and `intl_en.arb`.

## Initialization Order & App Lifecycle

```
[App Startup (main.dart)]
       │
       ├─► 1. WidgetsFlutterBinding.ensureInitialized()
       ├─► 2. LanguageProvider() instantiated
       ├─► 3. await languageProvider.loadSavedLocale()
       │        ├─► Reads SharedPreferences ('app_language_code')
       │        ├─► LanguageHelper.resolveLanguageCode() -> (saved or fallback 'it')
       │        └─► LanguageHelper.setAppLocale()
       │
       └─► 4. runApp(JustUsApp(languageProvider: languageProvider))
                └─► MaterialApp rebuilt via Selector2(languageProvider.locale)
```

### Background Isolate Initialization (Push Notifications)
When a push notification arrives while the app is killed/backgrounded:
1. `_firebaseMessagingBackgroundHandler` is triggered in a separate Dart VM isolate.
2. Calls `WidgetsFlutterBinding.ensureInitialized()`.
3. Calls `LanguageHelper.initFromSystemLocale()`.
4. Obtains system locale via `ui.PlatformDispatcher.instance.locale`.
5. Resolves against supported locales (`it`/`en`) and initializes `LanguageHelper.appLoc` to display localized local notifications.

## Locale Resolution & Fallback Matrix

| Scenario | System/Input Locale | Resolved Locale | Strategy |
| :--- | :--- | :--- | :--- |
| First launch (No saved locale) | System `it_IT` | `it` | Exact match |
| First launch (No saved locale) | System `en_US` | `en` | Match by language code |
| First launch (No saved locale) | System `fr_FR` | `it` | Unsupported -> Fallback to `it` |
| Saved preference | `'en'` | `en` | Loads stored string from `SharedPreferences` |
| Corrupted preference | `''` / `null` | `it` | Fallback to `it` |
| Missing translation key | Defined in `it`, missing in `en` | `it` string | Flutter `gen_l10n` fallback to base ARB |

## Runtime Locale Switching & Persistence

1. User opens Settings -> Language Screen ([localization_screen.dart](file:///f:/JustUS/Flutter/lib/features/settings/screens/localization_screen.dart)).
2. Taps on language option (e.g., English).
3. Executes `context.read<LanguageProvider>().setLanguageCode('en')`.
4. `setLocale()` executes:
   - Validates if target language differs from current language.
   - Updates `_locale` state.
   - Updates `LanguageHelper.setAppLocale(resolvedLocale)`.
   - Calls `notifyListeners()`.
   - Asynchronously persists `'en'` to `SharedPreferences` (`app_language_code`).
5. `MaterialApp` rebuilds reactively via `Selector2` without requiring an app restart.

## Backend Notification Localization Engine

Push notifications generated by the Node.js Express backend ([notification.service.js](file:///f:/JustUS/Backend/features/notifications/notification.service.js)) use a dedicated server-side localization engine.

### Backend `LOCALIZATIONS` Catalog

Server notification templates support `it` and `en` across key events:

| Notification Key | Italian Title / Body Template | English Title / Body Template |
| :--- | :--- | :--- |
| `requestAccepted` | **Richiesta Accettata** / `{partnerName} ha accettato la tua richiesta` | **Request Accepted** / `{partnerName} accepted your request` |
| `missyou` | **Mi manchi** / `{partnerName} sente la tua mancanza` | **Miss You** / `{partnerName} misses you` |
| `moodUpdated` | **Nuovo Umore** / `{partnerName} ha aggiornato il suo umore` | **New Mood** / `{partnerName} updated their mood` |
| `answerSubmitted` | **Nuova Risposta** / `{partnerName} ha risposto alla domanda` | **New Answer** / `{partnerName} answered the question` |
| `newQuestion` | **Nuova Domanda di Coppia** / `Una nuova domanda ti aspetta!` | **New Couple Question** / `A new question awaits you!` |
| `driveItemAdded` | **Nuovo Ricordo Aggiunto** / `{partnerName} ha aggiunto un ricordo` | **New Memory Added** / `{partnerName} added a memory` |
| `reactionAdded` | **Nuova Reazione a un Ricordo** / `{partnerName} ha reagito con {emojiChar}` | **New Reaction to a Memory** / `{partnerName} reacted with {emojiChar}` |
| `bucketItemAdded` | **Nuovo Desiderio nella Lista** / `{partnerName} ha aggiunto un desiderio` | **New Wish in the Bucket List** / `{partnerName} added a wish` |
| `default` | **JustUS** / `Hai una nuova notifica` | **JustUS** / `You have a new notification` |

### Backend Translation Resolution Logic
- Function `localizeNotificationText(key, params, locale)` resolves the target language.
- If requested `locale` is unsupported or missing, defaults to `'en'`.
- If key is unrecognized, falls back to `default` template.

## Alignment Audit & Findings

1. **Frontend-Backend Key Consistency:**
   - **Status:** **ALIGNED**. All notification event keys sent by Flutter (`requestAccepted`, `missyou`, `moodUpdated`, etc.) match the keys defined in `notification.service.js`.

2. **Hardcoded User-Facing Strings Audit:**
   - **Frontend UI:** **95% LOCALIZED**. Screens use `context.loc.*`.
   - **Exceptions/Findings:**
     - Database exception messages (e.g. `'Utente non autenticato o ID non valido'`, `'Hai gia una partnership o una richiesta attiva'`) returned from Supabase RPC functions are hardcoded in Italian.
     - Fallback error messages in `ErrorHandler` contain hardcoded English strings.
